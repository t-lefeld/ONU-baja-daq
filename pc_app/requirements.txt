# Ground station dependencies.
#
# aiohttp serves the dashboards, which are the UI now - it is not optional
# any more. pyserial talks to the E22 dongle. That is the whole runtime.
aiohttp>=3.9
pyserial>=3.5

# PySide6 is NOT required. The native window it powered (telemetry/qt_app.py,
# reachable via `run.py --native`) is retired: it only ever spoke v1's 3-node
# channel set, and it pulled a full GUI toolkit in for one window that the
# browser dashboards replaced. Install these two only if you specifically
# want --native back:
#   PySide6-Essentials>=6.5
#   shiboken6>=6.5
#
# If you do, use PySide6-Essentials rather than the "PySide6" umbrella
# package - the umbrella pulls in PySide6-Addons, which bundles QtWebEngine,
# an entire embedded Chromium, for a window that only ever used
# QtCore/QtGui/QtWidgets.

# Only needed to build the .exe (see build.bat):
#   pyinstaller>=6.0

# Only needed for tools/test_dbc.py and tools/test_dbc_v2.py:
#   cantools>=39

# python-can is NOT required. It only powers telemetry/can_adapter.py
# (CanAdapterSource), which taps a USB-CAN adapter (CANable/slcan, PCAN,
# Kvaser, socketcan) directly instead of going through the E22 dongle and
# the hub's own reassembly - useful for bench-testing nodes with no hub
# present. can_adapter.py imports python-can lazily inside the constructor
# specifically so that its absence never breaks `import telemetry.can_adapter`
# or the frozen Telemetry.exe for the (normal) case of a user with only a
# serial dongle. Install this only if you actually have a USB-CAN adapter
# and want --source can:
#   python-can>=4.3
